# Hybrid Capture

## Purpose

이 문서는 기존 HYBRID_CAPTURE 구현 계획이 현재 단일 촬영 구조로 대체된 결정과 그 이유를 기록한다.

HYBRID_CAPTURE는 별도의 런타임 기능으로 구현하지 않는다.

---

## Decision

2026-09-07, 촬영 방식 선택 분기를 제거하고 하나의 촬영 Session에서 자동 타이머와 카메라 물리 셔터를 함께 사용할 수 있는 구조를 유지하기로 결정했다.

사용자는 AUTO_TIMER, PHYSICAL_SHUTTER, HYBRID 중 하나를 선택하지 않는다.

시작하기 버튼을 누르면 기존 촬영 Session이 시작되며, 사용자는 자동 타이머를 이용하거나 카메라 셔터를 직접 눌러 촬영할 수 있다.

---

## Reason

실제 카메라 테스트에서 자동 타이머 진행 중 물리 셔터 촬영이 정상 처리되었다.

물리 셔터로 생성된 사진은 기존 파일 감지 및 촬영 완료 파이프라인을 통해 애니메이션, 썸네일, Gallery, COPY 및 다운로드까지 정상 처리되었다.

자동 타이머가 0초에 도달했을 때의 촬영도 정상 작동했다.

따라서 동일한 기능을 위해 별도의 HYBRID_CAPTURE 상태 관리자나 촬영 완료 로직을 추가할 필요가 없다.

---

## Current Architecture

촬영 요청의 출처와 실제 촬영 완료를 분리한다.

자동 타이머 촬영은 기존 촬영 Service에 요청을 전달한다.

물리 셔터 촬영은 카메라에서 직접 발생한다.

실제 사진 파일이 도착한 이후에는 기존 FILE_WATCH와 촬영 완료 파이프라인을 재사용한다.

촬영 출처에 따라 별도의 Session Folder, 썸네일, Gallery 또는 COPY 로직을 만들지 않는다.

---

## Timer Policy

자동 타이머의 카운트다운, 0초 촬영 요청, 완료 대기 및 다음 카운트다운 정책은 AUTO_TIMER.md를 따른다.

물리 셔터 촬영을 이유로 별도의 타이머 초기화 또는 중단 로직을 추가하지 않는다.

기존에 계획했던 “물리 셔터 촬영 완료 후 타이머를 10초부터 재시작하는 HYBRID 전용 정책”은 구현 계획에서 제외한다.

---

## Removed Plans

다음 계획은 현재 개발 범위에서 제거한다.

* AUTO_TIMER / PHYSICAL_SHUTTER / HYBRID 촬영 방식 선택 UI
* HYBRID 전용 상태 관리자
* HYBRID 전용 촬영 완료 파이프라인
* 촬영 출처별 Session Folder 분리
* HYBRID 전용 타이머 Reset 로직
* HYBRID captureMode 설정값 추가
* 물리 셔터 전용 모드의 선행 구현 요구사항

현재 정상 작동하는 기존 촬영 파이프라인을 유지한다.

---

## Verification Boundary

실제 카메라 물리 셔터 촬영은 검증되었다.

카메라 리모콘 촬영은 아직 실측하지 않았다.

리모콘이 카메라 셔터와 동일하게 촬영을 발생시키는 경우 기존 파일 감지 파이프라인에서 처리될 가능성이 높지만, 실제 호환성은 별도 확인이 필요하다.

리모콘 검증을 위해 새로운 촬영 모드를 미리 구현하지 않는다.

---

## Future Changes

향후 실제 운영에서 별도의 촬영 방식이나 충돌 정책이 필요해지는 경우, 구체적인 요구사항과 재현된 문제를 먼저 문서화한 뒤 구현 여부를 결정한다.

현재 검증된 촬영 동작을 가상의 문제 때문에 변경하지 않는다.

---

## Source of Truth

현재 자동 타이머의 상세 정책은 AUTO_TIMER.md를 따른다.

물리 셔터의 상세 정책은 PHYSICAL_SHUTTER.md를 따른다.

파일 감지와 촬영 완료의 상세 정책은 각각의 담당 문서를 따른다.

이 문서는 과거 HYBRID_CAPTURE 계획의 대체 결정만 기록하며, 현재 촬영 기능의 상세 정책을 중복 정의하지 않는다.
